# Board modules

Each board is a **self-contained directory**. Adding support for a machine means
adding one directory and re-running the index generator — no code changes.

```
boards/
  index.json              registry, generated by tools/make-index.py
  hp-z840/
    profile.json          component id -> rectangle, plus `match` criteria
    board.webp            the picture, referenced relatively from profile.json
    README.md             provenance: what is verified, what is inferred
```

## Adding your board

Full instructions, including how to find your component IDs and why the layout
cannot be auto-detected, are in [../AGENTS.md](../AGENTS.md). The short version:

```sh
sudo /usr/local/bin/dimm-mce-export --verbose      # produce a component list
./tools/calibrate.py ~/Desktop/my-board.png        # drag a box over each part
mkdir -p boards/<vendor>-<model>
mv profile.json my-board.png boards/<vendor>-<model>/
python3 tools/make-index.py                        # refresh the registry
```

Then reinstall, or copy the directory into
`~/.local/share/dimm-mce-monitor/boards/` and reopen the widget.

## How detection works

QML cannot list a directory, so `index.json` maps DMI identity to a board
directory. The widget loads the index, picks the first entry whose `match`
block equals this machine's DMI values (case-insensitive; empty values are
ignored), and loads that directory's `profile.json`.

The user data directory is searched **before** the copy inside the applet
package, so a local board module overrides a shipped one of the same name.

Your machine's identity:

```sh
cat /sys/class/dmi/id/board_vendor /sys/class/dmi/id/board_name \
    /sys/class/dmi/id/product_name
```

Match on `board_vendor` + `board_name` where you can — `product_name` varies
between SKUs of the same board. Include only the keys you actually want
compared; every key you list must match.

## Contributing

A board module is useful to other people even if it is incomplete — placing just
the DIMM and PCIe slots is worth having. Please do include:

- `README.md` in the board directory saying **where the picture came from** and
  which mappings you *verified* versus *inferred*.
- An honest `confidence` in `profile.json`: `user-calibrated` if you placed the
  boxes yourself against a real picture, `derived` if any identity or position
  is inferred. `derived` makes the widget show a visible caveat, which is the
  point — a confidently-wrong DIMM position sends someone to pull the wrong
  stick.

Pictures must be something you have the right to redistribute. Vendor service
manual diagrams are often clearer than photographs anyway, because they are
drawn orthographically and already carry silkscreen labels.
